# Trip Tags Implementation Plan

**Goal:** Trips carry tags that can be replaced over HTTP, and the trip list can be filtered by one tag.
**Architecture:** `tags` joins `ITrip` and is normalised once, in the store. The router gains `PUT /trips/:id/tags` and reads `?tag=` on `GET /trips`; both delegate to the store.
**Requirements source:** api's brief from `../plans/2026-10-25-trip-tags.md`
**Commands:** build `npm run build` · test `npm test`
**Plan status:** approved
**Orchestration:** `../plans/2026-10-25-trip-tags.md` · component api

## Milestone 1: Tags on trips

**Size:** S
**Goal:** A client can replace a trip's tags and every trip it reads back carries them, normalised.
**Depends on:** none
**Contracts:** the manifest's `ITrip` and `PUT /trips/:id/tags`, copied:

```ts
interface ITrip {
  id: string;
  name: string;
  startsOn: string;
  tags: string[];
} // tags trimmed, lowercase, unique, sorted
// PUT /trips/:id/tags { tags: string[] } → 200 ITrip | 400 { error } | 404 { error }
```

**Scenarios:**

- **Given** a trip with no tags **When** a client sets its tags to `[" Beach", "family", "beach"]` **Then** the trip comes back with `["beach", "family"]`
- **Given** a tagged trip **When** a client lists trips **Then** the trip carries its tags

### Ticket 1.2: PUT /trips/:id/tags

- **Status:** todo
- **Size:** S
- **Complexity:** moderate
- **Agent tier:** `sonnet`
- **Estimate:** `moderate` · stack `node` · baseline 0/0
- **Escalation:** none
- **Depends on:** Ticket 1.1
- **Files:**
  - Modify: `src/trips/router.ts`
  - Test: `src/trips/router.spec.ts`

**Context:** `tripsRouter(store)` in `src/trips/router.ts` returns a `node:http` handler; it matches `url.pathname` by hand and answers through `send(res, status, body)`. Add `PUT /trips/:id/tags`: read the body with `readJson`, reject anything that isn't `{ tags: string[] }` or carries a tag that is empty after trimming with 400, call `store.setTags` (Ticket 1.1), 404 on `undefined`, else 200 with the trip. Specs start the handler with `createServer(tripsRouter(createStore())).listen(0)` and use `fetch` against it.

**Acceptance criteria:**

- [ ] `PUT /trips/<id>/tags` with `{ "tags": ["Beach"] }` returns 200 and the trip with `tags: ["beach"]`
- [ ] A body without `tags`, with a non-string tag, or with `"  "` as a tag returns 400 with an `error` string
- [ ] An unknown id returns 404 with an `error` string
- [ ] `GET /trips` afterwards returns the trip with its new tags

## Milestone 2: Filter trips by tag

**Size:** S
**Goal:** `GET /trips?tag=<tag>` lists only the trips carrying that tag.
**Depends on:** Milestone 1
**Contracts:** the manifest's `GET /trips?tag=`, copied: `GET /trips?tag=<tag>` → 200 `ITrip[]` — only trips carrying `<tag>` after normalising; no param → every trip.
**Scenarios:**

- **Given** trips tagged `beach` and `city` **When** a client asks for `?tag=Beach` **Then** only the `beach` trips come back

### Ticket 2.1: ?tag= on GET /trips

- **Status:** todo
- **Size:** S
- **Complexity:** mechanical

**Context:** After Milestone 1, `IStore.list()` returns every trip and the store owns tag normalising. Give `list` an optional `tag?: string`, normalised the same way, and read `url.searchParams.get('tag')` in the `GET /trips` branch of `tripsRouter`. An empty `?tag=` behaves like no param.

- [ ] `GET /trips?tag=beach` returns only trips whose `tags` include `beach`
- [ ] `GET /trips?tag=Beach` returns the same trips as `?tag=beach`
- [ ] `GET /trips` and `GET /trips?tag=` return every trip
