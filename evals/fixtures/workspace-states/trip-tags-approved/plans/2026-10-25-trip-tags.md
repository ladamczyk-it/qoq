# Trip Tags — fullstack plan

**Goal:** Users tag their trips and filter the trip list by tag, with tags stored server-side so they sync between devices.
**Requirements source:** "Users should be able to tag their trips and filter the trip list by tag. Tags live on the server so they sync between devices." · grilled
**E2E owner:** web — its last milestone is E2E delivery
**Plan status:** approved

---

## Contracts

```ts
// ITrip, as served by api and mirrored by web's src/api/trips.ts
interface ITrip {
  id: string;
  name: string;
  startsOn: string; // ISO date
  tags: string[]; // trimmed, lowercase, unique, sorted; [] when none
}

// PUT /trips/:id/tags  { tags: string[] }  → 200 ITrip
//                                          → 400 { error } — tags missing, not an array of strings, or a tag empty after trimming
//                                          → 404 { error } — no trip with that id
// GET /trips?tag=<tag>                     → 200 ITrip[] — only trips carrying <tag> (matched after the same normalising); no param → every trip
```

| Contract              | Provider | Consumers |
| --------------------- | -------- | --------- |
| `ITrip.tags`          | api      | web       |
| `PUT /trips/:id/tags` | api      | web       |
| `GET /trips?tag=`     | api      | web       |

## Scenarios

- **Given** a trip with no tags **When** the user adds "Beach" and "family" to it **Then** the trip shows the tags `beach` and `family` — touches web, api
- **Given** tagged trips **When** the user picks the tag `beach` **Then** only trips tagged `beach` are listed, and clearing the filter lists every trip again — touches web, api
- **Given** the user tagged a trip on one device **When** they open the trip list on another **Then** the same tags are there — touches web, api
